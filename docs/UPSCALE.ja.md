# 画面を大きくする — アップスケール手順

Studio Miris 製ノベルゲーム（AXRe + VNEG エンジン）の画面を **640×480 → 1280×960**
などに拡大する手順です。翻訳とは独立していて、**日本語のまま解像度だけ上げる**用途にも
そのまま使えます。

> 言語 / Language: **日本語** · [한국어](../GUIDE.md)

---

## 何を道具がやり、何を自分でやるのか

拡大は「画像を大きくする」だけでは終わりません。ウィンドウの位置、文字の大きさ、
ボタンの当たり判定——**座標が全部ずれます**。そこが面倒なところで、道具はそれを引き受けます。

| | 担当 |
|---|---|
| 画面サイズ・ウィンドウ座標・UI 部品の位置 | **道具**（`ujyu build`） |
| exe 内の解像度定数 | **道具**（`ujyu scale exe`） |
| 画像を綺麗に引き伸ばすこと | **あなた**（外部アップスケーラ） |

画像を用意しなくても動きます。その場合は bilinear で伸ばすだけなので、**眠い絵**に
なります。せっかく大きくするなら AI アップスケーラを通す価値があります。

---

## 用意するもの

- ゲーム本体（**この道具にはゲームのファイルは一切含まれていません**）
- Python 環境 + このリポジトリ
- 画像アップスケーラ（任意）— Topaz Gigapixel、waifu2x、Real-ESRGAN など

---

## 手順

### 1. 倍率を決める

タイトル側の `config.py` に書きます。

```python
SCALE = 2                 # 1（原寸）/ 2 / 3
ORIG_W, ORIG_H = 640, 480 # 原寸（common.csv から自動で入ることが多い）
```

3× も動きますが画面が大きくなりすぎます。**2× が無難**です。

### 2. 元の画像を書き出す

```bash
ujyu unpack                                   # アーカイブを展開
ujyu scale cg-export <元の cg アーカイブ> --out work/
```

`work/1x/` の下に振り分けられます。

| フォルダ | 中身 | アップスケーラの必要性 |
|---|---|---|
| `art/` | 背景・立ち絵など画面いっぱいの絵 | **効果が大きい** |
| `small/` | サムネイル・ボタン・ロゴなど小物 | 単純リサンプルで十分なことが多い |
| `translated/` | 文字が描き込まれていて差し替え済みのもの | **要注意**（下記） |

同時に `work/_manifest.tsv` が作られます。どのファイルを何ドットにすべきかの一覧で、
あとの検査に使います。**手で編集しないでください。**

> `cg-export` は 1× のまま残す UI 画像も含めて**全部**書き出します。あとで拡大対象に
> 変えたときに素材が無くて困らないようにするためで、使わなければ無視されるだけです。

### 3. アップスケーラにかける

**出力は別のフォルダに**。`1x/` を上書きしないでください。

```
work/1x/   ← 入力（そのまま残す）
work/2x/   ← 出力（ファイル名は同じまま）
```

守ること：

- **ファイル名は変えない。** 道具は名前で対応を取ります（サブフォルダは辿ります）
- **寸法はちょうど原寸×N。** 半端だとゲームがサーフェスの大きさと食い違ってクラッシュ
  することがあります（道具が気づけばリサンプルで直しますが、当てにしないでください）
- **透過を潰さない。** アルファ付き PNG はアルファごと拡大してください

`translated/` は文字が描かれています。AI アップスケーラは文字を得意としません——潰したり
勝手に作り変えたりします。この分だけは**元の文字入り画像を作り直す**か、リサンプルで
済ませるほうが綺麗なことが多いです。

### 4. 結果を検査する

```bash
ujyu scale cg-check work/ work/2x/
```

抜け・寸法違い・アルファの欠落を洗い出します。**ここで 0 件にしてから**次に進みます。

### 5. 組み込む

`config.py` に置き場所を書いておくと `build` が拾います。

```python
CG_UPSCALE_DIR = dev("upscale", "2x")   # ここに置いた画像を使う
```

```bash
ujyu build            # SCALE>1 なら座標・exe・画像を全部まとめて処理
```

画像だけ差し替えたいときは：

```bash
ujyu scale cg <元の cg> --out <出力> --from-dir work/2x/
```

## 仕組み — なぜ座標の話が出てくるのか

`.scn`（シナリオ）の中に、ウィンドウの位置や大きさが数値で埋まっています。画像だけ
2 倍にすると、背景は大きいのにセーブ画面のボタンは左上 1/4 に固まる、という状態になります。

道具は座標を三つの経路で処理します。

| 経路 | 何を |
|---|---|
| `SCN_DIMS_AUTO` | VNEG のシンボルから座標を自動で見つけて ×N（**こちらが基本**） |
| `SCN_DIMS` | ファイル内の位置を直接指定して ×N（自動で拾えないものだけ） |
| `COMMON_CENTER` | 拡大しない 1× のままのウィンドウを、画面の中央へ寄せる |

**全部の画像を拡大するわけではありません。** メッセージウィンドウなど 1× のままにする
ものがあり、その上に載る枠やカーソルも 1× に揃えます（`CG_UI_1X_PREFIX`）。逆に
背景や鑑賞画面は画面全体を覆うので必ず拡大します（`CG_CONTENT_PREFIX`）。

## つまずきやすいところ

**同じ数値が二か所で使われている。** ある値がログ画面の矢印の幅であると同時に、
名前欄の文字サイズでもある——ということが起きます。そのまま ×N すると名前の文字だけ
大きくなります。`SCN_REPOINT` で参照を分けて解決します。

**×N が常に正解ではない。** 曲名の文字サイズなどは 2 倍にすると行に対して大きすぎます。
`SCN_VALUE_REMAP` で一段下げます。

**シーンを詰め直したらジャンプテーブルの貼り直しが要る。** これを忘れるとムービーや
選択肢でハングします。`ujyu build` は自動でやります。

**Windows 8 互換モードが必要**なことがあります（exe のプロパティ → 互換性）。
